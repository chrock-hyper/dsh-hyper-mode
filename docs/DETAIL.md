# 混合工具执行

内置的两种执行器是互斥的：`tool-executor-native` 让模型直呼每个可见工具，`tool-executor-ptc` 只允许直呼 `run_code`，其余工具全部退化为程序内的 SDK 绑定。本插件把两者合成一个作用域内的执行器。

## 它做什么

- **同一个 agent 同时拥有两种调用面**：`run_code` 传输与全部原生工具 schema 一并通告。
- **一批调用按调用形状分段执行**：相邻的同类调用合成一段，交给对应的执行器；段与段之间串行，保住「独占调用构成屏障」的语义。
- **结果按模型原始调用顺序归位**：段内各自保序，合批时用 `callId` 还原提交顺序。
- **提示词自己重写**：丢弃 PTC 的「只有 `run_code` 可直呼」规则，换成双面说明，再附上由 `renderToolsSdk` / `renderToolsSdkPy` 生成的 SDK 块。

## 什么时候两种都想要

- 长编排（`workflow`、`subagent`）：直呼，不受 `run_code` 的 10 分钟硬上限约束。
- 批量与封装（遍历 slots / configs、批量比对、只把结论带回对话）：写程序走 `run_code`。

## 已知限制

- **跨段不并发**：混合批按段串行执行，牺牲一点吞吐换取写操作的屏障语义。纯直呼或纯程序的批次走单执行器快路径，不受影响。
- **`run_code` 的额度与超时**沿用 PTC 运行时：默认 120 s、上限 600 s（含嵌套工具与审批等待），额度按 `maxSubCallsPerMinute` × 超时分钟数计算。
- **两个执行器实例各有一条 pipeline**：权限策略、审批、取消、日志都由共享的 `ToolExecutionPipeline` 处理，因此两者行为一致；但每个执行器只结算自己的那一段。
- **依赖 PTC 运行时**：没有挂载 `ptcRuntime` 时插件不激活（`inject` 声明了它）；运行时语言不受支持时退化为纯原生面，不再通告 `run_code`。
