      布局与信息架构（图示）

      两个新视图都挂在会话级 conversation.view 槽位：对话 0 · 轨迹 10 · 统计 40 · 岗位 50 · Wiki 60。会话结束就没有这两个 tab，不需要项目管理器。

      图 1 · 岗位 tab（三栏）

      1作用域与筛选本项目 / 全局切换；搜索框；新建岗位 就地展开表单（不再用浏览器弹窗）
      3角色卡编辑器名称 · 能力 · 技能 · 交接 · 权限；正文 Markdown；岗位指导折叠区；顶栏 保存/归档/复制提示词
      5经验与指导最近经验（时间 + 来源）、追加输入框；指导路径指向 wiki 页面
      2岗位列表名称 + id · vN；「覆盖全局」「随包」徽标；归档项置灰
      4状态区版本与未保存提示；冲突横幅（v3 → v4）带「重新载入」；保存失败/成功就地在顶部显示
      • 项目作用域来自会话：tab 自带 sessionId，Host 用它取会话工作目录，不再需要选目录。
      • 只读随包岗位：列表尾部单列，点「复制到本项目 / 全局」才可编辑。
      • 所有按钮都有三态：可点 / 执行中（禁用 + 文案变化）/ 失败（顶部错误条 + 可重试），不会出现“点了没反应”。

      图 2 · Wiki tab（三栏）

      1页面树 + 搜索按目录分组；有草稿的页面带橙点；作用域切换同岗位
      3页面编辑标题与元信息；源码 / 预览 切换；人的写入直接保存页面（Agent 只能写草稿）
      5草稿与反链unified diff（+/- 着色）、批准 / 打回（填理由）/ 强制覆盖；反链列表
      2待审计数tab 标题上的角标（2）；批准后即时减一
      4草稿横幅页面顶部提示“有 1 份待审草稿（来自 lead，基于 v3）”，可跳到右侧 diff
      • 基线哈希冲突：页面在草稿期间被改过时，批准按钮变为「强制覆盖」并给出二次确认文字，而不是静默覆盖。
      • 打回闭环：理由写回草稿的 draft.reason，Agent 用 wiki status 读到后再改。
      • 两库独立：本项目 / 全局两棵树，同名页面互不影响；全局库批准后自动 git 提交。

      图 3 · 一次点击的数据流

      tab 组件（sessionId）→ connection.rpc（已鉴权）→ Host store（同一套函数）→ .dsh/roles · .dsh/wiki 文件→ 面板回读刷新
      • 面板与 Agent 工具调用同一组 store 函数，不维护第二套逻辑。
      • 数据通道改用 ctx.connection.rpc：面板请求带宿主已有的浏览器凭据，不再出现 401 后“静默没反应”。
